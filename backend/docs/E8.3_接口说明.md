# E8.3 实验接口说明（对接文档）

版本 v1.0，2026-09-16。对应 PR #30（E8.3 POI局部发现冻结版），算法现状以 [当前算法版本_E8.3](当前算法版本_E8.3.md) 为准。

本文档描述 PR #30 暴露的**实验侧**接口：`run_task`、`compute_multicross_boundary`、实验 CLI、端点模型快照，以及 `RouteObservation` / `BaiduProvider` 的行为变化。便于实验复现、离线工具和后续验证对接。

## 0. 对接边界（先读）

- 本文档**不是**生产 HTTP API 文档。PR #30 未把生产 API、前端流程、设施 1000 米规则切换到新入口，也没有新增前端字段。
- 联合任务入口 `tools.endpoint_e83_poi.run_task` **仅接受离线 Provider**；传入 `provider.network=True` 会直接 `ValueError`。
- 所有实验入口默认阻断网络（`tools.diagnostic_common.no_network`）；真实路线必须走独立 live 入口并显式授权与预算。
- 如果对接目的是前端/生产，请先另行冻结生产 API 契约，不要直接依赖本文字段。

## 1. 环境与依赖

- Python 3.11；依赖沿用 `backend/requirements.lock.txt` 与 `life-circle-algorithm/pyproject.toml`，无新增依赖。
- 从仓库根目录运行：

```powershell
$env:PYTHONPATH="$PWD/backend;$PWD/life-circle-algorithm/src"
$env:PYTHONDONTWRITEBYTECODE='1'
```

- 实验输出目录**必须尚不存在**（`output.mkdir(exist_ok=False)`）；不得覆盖已有结果。

## 2. 关键数据模型

### 2.1 RouteObservation（`life-circle-algorithm/src/life_circle/models.py:69`）

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `destination` | `(lng, lat)` | 请求的目的地 |
| `duration` | `float \| None` | 请求点有效耗时；`reason` 非空时为 `None` |
| `reason` | `str \| None` | `None` 表示请求点有效；否则为失败/无效原因 |
| `observed_duration` | `float \| None` | **新增**：路线实际端点耗时，端点偏移被拒时仍保留 |
| `origin_offset_m` / `destination_offset_m` | `float \| None` | **新增**：起/终点实际位置与请求位置的偏移（米） |
| `endpoint_verified` | `bool` | 首末分段端点**解析成功**即为 `True`，不代表偏移 ≤50 米 |
| `route_origin` / `route_destination` | `(lng, lat) \| None` | 实际绑路端点 |
| `request_origin` | `(lng, lat) \| None` | 该次物理请求的起点 |
| `attempts` | `int` | 物理尝试次数 |
| `distance_m` / `route_path` | `float \| list` | 距离与路径点 |

判定规则：`duration = None` 当且仅当 `reason` 非空；`reachable` 属性仅在 `duration` 有效时给出 `duration <= 900`。**unknown（`duration=None`）不得当作不可达。**

### 2.2 BaiduProvider 端点偏移行为（`life-circle-algorithm/src/life_circle/providers.py:90`）

旧行为：偏移 >50 米的路线被丢弃，只返回 `endpoint_offset`。新行为：

- 偏移 ≤50 米的路线进入正常候选，按 `route_metric`（`duration`/`distance`）选最优。
- 偏移 >50 米的路线**不再丢弃**：返回 `reason='endpoint_offset'`，并携带 `observed_duration`、`route_origin`、`route_destination`、`origin_offset_m`、`destination_offset_m`、`endpoint_verified`。
- 当没有合格路线但有偏移路线时，返回偏移路线作为证据；`duration` 仍为 `None`。

对接注意：**判断入口有效必须同时看 `reason is None` 与偏移字段**；不能只看 `endpoint_verified`，也不能把 `observed_duration` 当请求 POI 入口的耗时直接使用。

### 2.3 POI 目录与需求

`run_task` 的固定任务输入：

```json
{"id": "p000", "coordinate": [121.517526, 31.313077], "critical": true}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 任务内唯一字符串；重复或 demand 引用不存在的 id 会 `ValueError` |
| `coordinate` | BD09LL `[lng, lat]` |
| `critical` | 关键 POI，需在早期阶段完成核验 |
| `uid` | 合成工作负载不允许设置（设置后抛 `ValueError`），真实 UID 请求不在本接口范围 |
| `demand` | id 列表，按固定任务全部核验；预测结果不会过滤该列表 |

## 3. `run_task`：E8.3 联合任务入口

位置：`backend/tools/endpoint_e83_poi.py:78`。

```python
async def run_task(case, provider, pois, demand, *, circle_budget, poi_budget, shared,
                   token=None, run_id='offline-task', poi_policy='critical')
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `case` | 是 | 场景名，进入证据上下文，用于隔离缓存 |
| `provider` | 是 | 离线 Provider：`network=False`、`identity`、`calls` 计数、`query_walking_time(origin, destination, deadline)` |
| `pois` / `demand` | 是 | 见 2.3 |
| `circle_budget` / `poi_budget` | 是 | 构圈与 POI 核验预算，分别计数，均不得为负 |
| `shared` | 是 | `True` 时启用共享证据与 POI 引导策略 |
| `token` | 否 | `CancelToken`，取消后停止后续调用 |
| `run_id` | 否 | 证据上下文中的运行标识，影响缓存隔离 |
| `poi_policy` | 否 | `critical` / `early` / `guided` / `discover`；`shared=False` 时只允许 `critical` |

约束：`provider.network=True`、负预算、非法 `poi_policy`、重复 id、非法目录均抛 `ValueError`。实验必须在 `no_network()` 内运行。

### 返回结构

| 键 | 说明 |
| --- | --- |
| `circle` | `compute_multicross_boundary` 的结果（见第 4 节），失败时为 `None` |
| `circle_error` | `GeometryError` 文本或 `None` |
| `poi` | `{poi_id: status}`，状态见下 |
| `cost` | `circle_calls`、`poi_calls`、`retries`、`total_calls`、`retrieval_calls=0`、`reference_calls=0` |
| `sharing` | `circle_to_poi`、`poi_imported`、`late_poi_imported`、`claimed_bracket_shrink_from_import`（恒为 0） |
| `first_coarse` | 首次粗圈时间点 `{total_calls, elapsed_s}` 或 `None` |
| `critical_ready` | 全部关键 POI 完成核验的时间点或 `None` |
| `elapsed_s` | 运行墙钟秒数 |
| `ledger` | 物理尝试账本，逐条 `{id, purpose, uses, attempt, destination, observation}` |

POI 状态机（`confirmed_poi`）：

| status | 含义 |
| --- | --- |
| `pending` | 未核验或证据无效；`reason` 为 `missing_observation` / `invalid_evidence` / `endpoint_mapping_unconfirmed` / 原始 reason |
| `verified_reachable` | 实际端点严格匹配请求起终点，且 `observed_duration <= 900` |
| `verified_unreachable` | 实际端点严格匹配，且 `observed_duration > 900` |

计数不变量（可直接断言）：`total_calls == len(ledger) == provider.calls == circle_calls + poi_calls`；`circle_calls <= circle_budget`、`poi_calls <= poi_budget`；重试计入对应预算。

## 4. `compute_multicross_boundary`：E8.2 构圈核心

位置：`backend/tools/endpoint_multicross_boundary.py:157`。

```python
async def compute_multicross_boundary(request, provider, token, *, radial_step=50, target=25,
    allow_network=False, parallel_sampling=False, edge_batch_size=1, on_checkpoint=None,
    diverse_batches=False, coverage_first=False, edge_queue_policy=None, on_local_start=None,
    poi_guided=False, poi_discovery_only=False)
```

| 参数 | 说明 |
| --- | --- |
| `request` | `IsochroneRequest`；真实网络 Provider 需 `allow_network=True` 才允许 |
| `target` | 混合边细化目标宽度（米），默认 25 |
| `edge_batch_size` | 1–30；>1 时先用批量中点采样再逐边细化 |
| `on_local_start` | `async def (session, rows)`：基本方向完成后、局部修复前调用，POI 引导入口 |
| `on_checkpoint` | `async def (value)`：每 200 次调用回调 `{calls, phase, unresolvedEdges, pendingUnattemptedEdges, pendingScanRays, unknownAreaM2, areaM2, negativeConflicts, geometry, unknownRegion}` |
| `poi_guided` / `poi_discovery_only` | 启用 POI 焦点优先 / 仅发现模式；需要 `on_local_start` 内已导入 POI 证据 |

### 返回结构

- 基础（径向）：`status`（`completed`/`cancelled`）、`algorithm='local-multicross-e82'`、`center`、`calls`、`phases`、`geometry`、`directions`、`truncated`、`stopReason`、`negativeEvidence`、`candidateGeometry`、`uncertaintyBand`。
- 局部修复：`localRepair`（`patches`、`calls`、`scanRays`、`edgeBrackets`、`edgeBatches`、`poiGuidance`、`negativeConflicts`、`seamExpandedAreaM2`、`unknownAreaM2`、`patchGeometry`、`connectionAssumption`）、`completion`、`uncertainty`、`negativeEvidence`（含 `coordinateLocal`、`insideEstimate`、`physicalBarrierVerified=False`）。
- `run_task` 追加：`observationEvidence`、`phases`、`poiReconnection`、`prePoiCompletion`。

语义要点：

- `quality`：`experimental_partial_local_repair`（正常局部修复）或 `experimental_evidence_conflict`（已知负证据落入估计内，`geometry=None`）。
- `completion.scope='observed_local_boundary_only'`；`resolutionReached=True` 需要无未解边、扫描完成、无冲突、未知面积 <1e-6；`budgetExhausted` 表示预算耗尽。
- `uncertainty.guaranteedCoverage` 恒为 `False`；`unknownRegion` 是未定位局部面，不是不可达区。
- 取消：`status='cancelled'`，`geometry/candidateGeometry/unknownRegion` 置 `None`。

## 6. 端点模型快照接口

位置：`backend/app/endpoint_model.py`，版本常量 `VERSION='actual-endpoints-e5-v1'`。

```python
def build_endpoint_model(observations, origin, *, extent, radius, synthetic, cancelled=lambda: False)
```

- `observations`：具有 `destination`、`duration`、`reason`、`observed_duration`、`endpoint_verified`、`route_origin`、`route_destination`、`request_origin`、`origin_offset_m`、`destination_offset_m`、`attempts` 属性的记录（`RouteObservation` 可直接使用）。
- 只选“同一实际起点队列中样本最多”的一组；`excluded` 记录 `derived_origin_anchor`、`invalid_measurement`、`missing_endpoints`、`invalid_endpoints`、`different_origin`。
- 几何无效时抛 `ValueError('Actual endpoint geometry invalid')`。

`EndpointModel` 方法：

| 方法 | 说明 |
| --- | --- |
| `query_bd09(point, cancelled=...)` | BD09LL 查询；返回查询模型字段 + `inputCoordinateSystem='bd09ll'`、`inputPoint`、`projection`。`evidence` 为 `observed` / `interpolated` / `unknown`，`reason` 为 `outside_domain`、`outside_convex_hull`、`insufficient_geometry`、`radius_filtered`、`numerical_unresolved` 等 |
| `save(path)` | 写带 `sha256` 封装快照；路径父目录自动创建；文件已存在会失败 |
| `apply(result)` | 把估计几何写回结果对象：`geometry`、`local_geometry`、`local_unknown`、`unknown_region`、`unreachable_region`、`uncertain_region`、`computation_extent`、`statistics.unknown_area`、`quality`（`partial` 或 `insufficient`）、`warnings`（含 `endpoint_model_estimate`、`radius_policy_unvalidated`、必要时 `range_truncated`）、`time_bands` |

`load_endpoint_model(path)` 校验封装 `sha256`、`VERSION`、投影参数与模型身份，任一不符抛 `ValueError`。

## 7. 最小对接示例

```python
import asyncio
from life_circle.coordinates import normalize
from tools.diagnostic_common import no_network
from tools.endpoint_e83_poi import run_task
from tools.endpoint_radial_experiment import ORIGIN, P, Synthetic

pois = [
    dict(id='inside', coordinate=normalize(P.to_geographic((300, 0))), critical=True),
    dict(id='outside', coordinate=normalize(P.to_geographic((900, 0))), critical=True),
]

async def main():
    with no_network():  # 实验入口的网络守卫；真实网络需单独的 live 入口
        result = await run_task('circle', Synthetic('circle'), pois, ['inside', 'outside'],
                                circle_budget=200, poi_budget=2, shared=True)
    assert result['poi']['inside']['status'] == 'verified_reachable'
    assert result['poi']['outside']['status'] == 'verified_unreachable'
    assert result['cost']['total_calls'] == result['cost']['circle_calls'] + result['cost']['poi_calls']
    assert any(set(e['uses']) == {'circle', 'poi'} for e in result['ledger'])

asyncio.run(main())
```

## 8. 错误与 unknown 约定

- unknown / `pending` 不等价于不可达；`geometry=None` 表示证据冲突，不是空圈。
- 不得从 `observed_duration` 直接推断请求 POI 入口可达；必须用 `confirmed_poi` 的严格端点匹配。
- 负证据 `physicalBarrierVerified` 为 `False`，只是“超过阈值”的观测；`insideEstimate` 表示其落在候选估计内。
- `confidence` / `accuracyValidated` 为空或未校准，`uncertainty.guaranteedCoverage=False`，不得对外声称覆盖率或准确率。
