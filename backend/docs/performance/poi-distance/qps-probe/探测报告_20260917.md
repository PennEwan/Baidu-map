# 新 AK 步行接口 QPS 试测（2026-09-17）

- 目标：新百度 AK，`baidu/directionlite/v1/walking`。
- 授权：两轮，各自 ≤60 次真实请求、最高 20 QPS、遇 `rate_limit/quota/permission` 立即停。
- 工具：`backend/tools/qps_probe.py`（`plan` 零请求；`live` 必须 `--accept-quota`，`--concurrency` 上限 3）。
- 产物：计划 [plan.json](plan.json)、单飞结果 [live-20260917.json](live-20260917.json)、并发结果 [live-concurrency3-20260917.json](live-concurrency3-20260917.json)；均不含 AK、URL、请求头。

## 第一轮：单飞（并发 1）

`python -m tools.qps_probe --mode live --output .../live-20260917.json --accept-quota`

51 次全部成功、0 次 `rate_limit`，但单飞时一次只等一个响应，实际吞吐被响应时延封顶：

| 标称 QPS | 发送/成功 | 实际吞吐 |
| ---: | ---: | ---: |
| 1–8 | 1/1 … 8/8 | 2.2–3.9 /s |
| 12 | 12/12 | 5.10 /s |
| 20 | 20/20 | 8.85 /s |

结论：只能证明峰值约 **9 req/s** 未触发限流；标称 12/20 档**未真正达到**，不足以判断上限。

## 结论

- 新 AK 在本次范围内可稳定承受 **约 20 req/s**（20 次请求的 1 秒窗口内全部成功），未出现 `rate_limit/quota/permission`。
- 上限**仍未确定**：受授权封顶 20，未测试更高档；如需更高需再次授权。
- 该结果是"服务端是否限流"的实测，**不是控制台额度**，也未核验日额度，不能直接当作 `ANALYSIS_QPS` 的 console 依据。
