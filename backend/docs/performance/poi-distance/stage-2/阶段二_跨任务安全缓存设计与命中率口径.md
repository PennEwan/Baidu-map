## 1. 目标

低配额下并发改造收益有限，缓存优先：同一 OD 在跨任务、跨等时圈/设施流程中重复出现时，命中缓存可省下真实路线配额与 wall-clock。但缓存必须建立在业务语义等价与失败隔离之上，不能把不同入口、不同 metric 的数值互相折叠。

## 2. 键规范

`od_cache_key` 的键由以下字段组成，任一项不同即不命中：

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `provider` | 数据来源 | `baidu` 与 `synthetic` 不互通 |
| `api_version` | 接口与版本 | 如 `directionlite/v1/walking`；接口变更即失效 |
| `metric` | 选路目标 | `duration` 与 `distance` 结果不同，不得互换 |
| `coord_system` | 坐标系 | 如 `bd09ll`；坐标系不同不得按数值复用 |
| `origin` / `destination` | 起终点 | 六位小数归一化后比较 |
| `origin_uid` / `destination_uid` | 绑路入口 | **不同 UID 即使坐标相同也不得折叠**（设施入口可能不同） |

补充规则：

- 坐标只做六位小数归一，不做四舍五入折中；相近但不相同的点不视为同一 OD。
- 不同任务、等时圈与设施 provider 的 metric/UID 语义不同，不能只凭经纬度复用。
- 分析器统计 UID 变体组（同坐标不同 UID）的数量，用来量化"不可折叠"的比例，而不是把它们当作命中。

## 3. 可缓存判定与失败策略

只有同时满足以下两条的观测才可写入/复用缓存：

1. `reason is None`（调用成功且解析有效）；
2. `endpoint_verified is True`（具备 ≤50m 端点证据）。

以下情形一律不缓存（`UNCACHEABLE_REASONS`，`backend/app/stage_ledger.py:10`）：无结果、瞬时失败、timeout、限流、配额、权限、参数错误、取消、deadline、端点偏移、无效时长/距离、上游异常等。`reason is None` 但 `endpoint_verified` 非 `True` 的记录同样排除，在分析器中记为 `endpoint_unverified`。

关键语义：

- cache miss 不等于 `no_result`；不得把未命中或失败写成不可达。
- 无结果、失败不做负缓存；下一次仍需真实请求。
- 暖缓存不得与冷基线对比制造收益；命中率分析只使用已经发生过的真实记录，本轮分析器零请求。

## 4. TTL 与失效（政策）

- TTL 必须显式设置，禁止无限期缓存。
- provider / API 版本 / 坐标系 / metric 任一变化即整体失效，不复用旧键。
- 建议按 metric 与任务类型分组设置 TTL；具体秒数在真实基线与账户配额明确后约定，本轮**不虚构数值**。
- TTL 到期后重新请求，不把过期值当作成功观测。

## 5. 命中率口径与工具

输入 schema `od-observations-v1`（JSON 数组，或带 `observations` 的 JSON 对象，或 JSONL）：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `provider` / `api_version` / `metric` / `coord_system` | 是 | 参与键 |
| `origin` / `destination` | 是 | `[lng, lat]` 或 `{lng, lat}` |
| `origin_uid` / `destination_uid` | 否 | 参与键，默认空 |
| `task_id` | 否 | 用于区分跨任务重复 |
| `reason` | 否 | 失败/无结果原因；非空即不可缓存 |
| `endpoint_verified` | 否 | 只有 `true` 才可缓存 |

输出 schema `od-cache-review-v1`：

| 指标 | 定义 |
| --- | --- |
| `totals.potentialHitRate` | `(总观测 − 唯一键) / 总观测`，偏乐观上界 |
| `cacheable.potentialHitRate` | 仅在可缓存观测内计算，门禁采用该口径 |
| `cacheable.excludedReasons` | 被排除的失败/未核验计数 |
| `totals.crossTaskPotentialHitRate` | 同一键出现在 ≥2 个 `task_id` 时的冗余观测 / 总观测 |
| `uidVariantGroups.groups` | 同坐标不同 UID 的组数，禁止折叠 |

示例（[example-review.json](example-review.json)，合成数据）：8 条观测、4 个唯一键、总体潜在命中率 0.5、可缓存命中率 0.333333、跨任务命中率 0.125、1 个 UID 变体组、2 条不可缓存。

工具性质：零网络请求（`networkRequests: 0`）、不读取 AK/URL、输出已存在时拒绝覆盖、写盘前执行 `assert_no_secrets`。

## 6. 门禁与出口

阶段二出口（对齐 `scheme.md`）：

1. 有命中率数据（真实、可缓存、跨任务三个口径）；
2. 有键规范与失败不缓存策略；
3. 有回归证明不会把 unknown 写成不可达（`observation_cacheable(None, False) == False` 等测试）。

实现门禁：

- 只有**可缓存跨任务命中率超过约定阈值**时才实现 cache；阈值在真实基线与控制台配额明确后约定，本轮不预设数字。
- 若没有命中空间，则书面关闭缓存线，转而回到采样/候选上限等既有约束内优化。
- 任何实现另开代码审查，不把本准备代码直接当生产实现。

## 7. 拿到真实明细后的执行清单与执行记录

### 执行记录（2026-09-16，第一步）

可用来源核对：仓库与可达的 `D:/CodexOutputs` 中都没有生产运行的账本或逐点观测（`ledger.json`/`observations.json`/`point-evaluation.json` 均不存在）。仓库内唯一带真实坐标与耗时的已授权产物是 [国定一社区_边界参考点_v2.json](../../../国定一社区_边界参考点_v2.json)：固定参考集的 24 条连接线端点，共 48 条真实百度步行耗时；该冻结文件没有逐点端点核验字段。

执行：

```text

python -m tools.od_cache_review --input <新文件>.json --output <新文件>.json --label frozen-reference-v2
```

产物：[reference-v2-observations.json](reference-v2-observations.json)、[reference-v2-review.json](reference-v2-review.json)。

| 指标 | 值 | 解读 |
| --- | ---: | --- |
| 观测数 | 48 | 24 条连接线 × 2 端点 |
| 唯一键 / 重复观测 | 33 / 15 | 相邻连接线共享端点，单任务内重复率 31.25% |
| 可缓存观测 | 0 | 冻结文件未记录逐点端点核验，全部 `endpoint_unverified` |
| 可缓存命中率 | null | 没有可缓存观测，无法给出 |
| 跨任务命中率 | 0.0 | 单任务参考集，无跨任务重复 |

结论与限制：本步只证明"导出—复核"链路可用，并给出参考集的重复上界；31.25% 来自相邻线段共享端点，**不是**生产设施扫描的命中率，不能用于门禁。因冻结文件缺端点证据，按第 3 节规则 48 条全部不可缓存。

剩余缺口曾为"运行不记录逐 OD 观测"，本轮已补齐记录能力：

- `StageLedger.record_od` / `od_observations` / `od_payload` 记录 provider、API 版本、metric、坐标系、起终点、UID、reason、`endpoint_verified`、耗时与距离；`task_id` 由构造参数指定，用于跨任务统计；非百度 identity 一律跳过。
- 真实 walking 路径已接入：`LimitedProvider`（等时圈采样与路线点击）与 `facilities.analyze_facilities` 的 `route()`（设施样本→设施 UID，携带 `destination_uid`）只在挂载账本时记录，生产未挂账本时行为不变。
- `stage_baseline` 新增 `--observations-output` 与 `--task-id`：mock 冒烟已跑通"运行 → 落 `od-observations-v1` → `od_cache_review`"全链路（33 条观测、11 唯一键；mock 数据标注 `stage-baseline-mock`、`network: false`，**不得**用于门禁）。

因此下一步是：在控制台配额与预算明确后，用一次带账本的真实运行（live walking 固定中心，或未来的 live 设施流程）写出 OD sidecar，再跑分析器并按第 6 节决策。在拿到真实可缓存跨任务命中率前，不实现 cache。

## 8. 明确不做

- 不实现跨任务 cache、不改 Scheduler / Provider / 采样。
- 不用暖缓存对比冷基线，不为命中率删减观测。
- 不把坐标相同、UID 不同的 OD 合并。
- 不把 unknown、失败、无结果当命中，不做负缓存。
- 不读取或输出真实 AK、带凭据 URL。
