## 0. 结论

项目经历过两次目录整理：一次集中搬迁**在同一批改动里被撤回**，一次"先建索引、分批迁移"的方案**从未合入**。结果是仓库继承了两次整理的*产出*（根目录启动器、一个只装一份文档的 `docs/`），却没有继承任何一次的*规则*；两个独立仓库又被放在主仓库工作区内且未被忽略。

因此本方案不重做一次"大搬迁"，而是：

1. **先划边界、再建索引、最后分批迁移**（沿用未合入方案 `4c839bb6` 的策略，而不是被撤回的 `68c336c3`）。
2. **运行路径一律不动**：`backend/`、`life-circle-demo/`、`life-circle-algorithm/`、`data/`、三个启动器、契约生成目标在本次整理中保持原位。搬迁的每个路径都有代码级代价（见 §6）。
3. **两个独立仓库迁到与主项目同级**，各自保留 Git 历史、远端、CI 与 Pages 工作流；不采用 submodule/gitlink。

#### 顺手修掉一个已进 `main` 的问题：`node_modules` 被当成仓库内容提交

`#55` 在 `main` 上留下一条索引记录：

```text
120000 bdd824c1…  life-circle-demo/node_modules  ->  /home/tairitsu_tempest/Baidu-map/life-circle-demo/node_modules
```

即把**本机安装好的依赖目录**以符号链接提交，而且目标是绝对路径。它在本机看起来"没事"的原因很具体：
这个克隆的 `.git/config` 里是 `core.symlinks=false`（另有 `core.fileMode=false`），git 把这条记录落成
一个**内容为路径的普通文件**；正常克隆（含 CI）会得到一个指向别人机器的死链接。上一轮 `.gitignore`
里写的是 `life-circle-demo/node_modules/`，而**带尾斜杠的规则只匹配目录**，符号链接与普通文件都漏过。

处置（提交 `42039ec`）：删掉这条索引记录（本机依赖原样保留，仍未跟踪）；规则改成不带尾斜杠的
`/life-circle-demo/node_modules`；检查器加两条判据 —— 依赖路径不得进索引、索引里符号链接的目标不得是
绝对路径（后者读**索引里的 blob**，所以在 `core.symlinks=false` 的检出上照样成立）。

顺带把 git 的忽略语义实测清楚并写进自检（断言从 10 项加到 14 项）：`dir/` 形式的规则**只匹配目录**，
普通文件、符号链接、以及不存在的路径都匹配不到；不带尾斜杠的裸路径四种都匹配。用例四覆盖"被提交的
依赖"与"索引里的绝对路径链接"，用例五专门覆盖"忽略规则退回 `dir/` 形式"。

反向验证：把 `bdd824c1…` 这条记录原样写回索引，检查器退出码 **1** 并同时报出两条问题；回滚后退出码 **0**。
